## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Review text can be long and expensive to lose. One composer should support comments, review summaries, and PR descriptions with a clear distinction between draft and publish.

## Testing steps

1. Code/provider tests: Test Unicode caret/selection, multiline paste, draft recovery, editor failure, and account boundaries.
2. Real-binary TUI E2E scenario `composer`: Compose/paste/preview via keys and clicks, cancel and restart, open a fixture editor, and assert recovered text and zero publish commands until explicit Submit. Run fresh fixtures for keyboard and mouse paths and verify equivalent outcomes at 120x40 and 80x24 where applicable.
3. Run `cargo test --test tui_e2e composer -- --nocapture` and verify a nonzero selected test count; run the relevant code/provider tests and `cargo test --all-targets`. Record actual results and failure artifacts before completion. The initial framework is delivered by the bootstrap/framework prerequisites.
