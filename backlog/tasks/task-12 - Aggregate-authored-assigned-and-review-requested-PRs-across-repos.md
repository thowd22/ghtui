## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Tracking PRs should not require opening each repository separately. Authored, assigned, and review-requested memberships are distinct and can overlap.

## Testing steps

1. Code/provider tests: Check overlapping memberships, cross-repo number collisions, pagination/caps, scopes, stale refresh, and sorting.
2. Real-binary TUI E2E scenario `personal_inbox`: Load three repositories with overlapping queues, switch/filter/open rows using keys and clicks, refresh, and assert correct memberships and partial-result warnings. Run fresh fixtures for keyboard and mouse paths and verify equivalent outcomes at 120x40 and 80x24 where applicable.
3. Run `cargo test --test tui_e2e personal_inbox -- --nocapture` and verify a nonzero selected test count; run the relevant code/provider tests and `cargo test --all-targets`. Record actual results and failure artifacts before completion. The initial framework is delivered by the bootstrap/framework prerequisites.
