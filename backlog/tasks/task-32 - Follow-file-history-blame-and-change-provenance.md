## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Once a user finds a file or line, they should immediately see when it changed and navigate from that explanation back to the commit, diff, or PR.

## Testing steps

1. Code/provider tests: Generate renamed/merged files and verify history/blame against Git; test line mapping and missing-history states.
2. Real-binary TUI E2E scenario `file_history`: Open a file at an old revision, select a line/history entry via keys and clicks, follow it to graph/diff and back, and assert revision and provenance. Run fresh fixtures for keyboard and mouse paths and verify equivalent outcomes at 120x40 and 80x24 where applicable.
3. Run `cargo test --test tui_e2e file_history -- --nocapture` and verify a nonzero selected test count; run the relevant code/provider tests and `cargo test --all-targets`. Record actual results and failure artifacts before completion. The initial framework is delivered by the bootstrap/framework prerequisites.
