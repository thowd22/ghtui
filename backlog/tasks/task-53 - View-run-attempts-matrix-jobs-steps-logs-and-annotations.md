## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Troubleshooting requires finding the failed job or step immediately and seeing its context. Rerun attempts, matrix jobs and reusable workflows must not be flattened into misleading status.

## Testing steps

1. Code/provider tests: Test attempt/job IDs, matrix/reusable definitions, missing dependency data, log bounds, annotations and polling transitions.
2. Real-binary TUI E2E scenario `actions_run_view`: Open a matrix run and failed step via keys/clicks, search/scroll logs, jump to an annotation and refresh a progressing run; assert correct attempt and log context. Run fresh fixtures for keyboard and mouse paths and verify equivalent outcomes at 120x40 and 80x24 where applicable.
3. Run `cargo test --test tui_e2e actions_run_view -- --nocapture` and verify a nonzero selected test count; run relevant code/provider tests and `cargo test --all-targets`. Record actual results and failure artifacts before completion. Use the shared framework established by the bootstrap/framework prerequisites.
