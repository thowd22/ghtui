## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
All GitHub access and local Git operations depend on subprocesses. A hung process, prompt, large output, or ambiguous write must not freeze the app or cause a duplicate mutation.

## Testing steps

1. Code/provider tests: Use fixture children to verify argv/stdin, timeout cleanup, large output, exit codes, escape sanitization, and no automatic duplicate writes.
2. Real-binary TUI E2E scenario `process_runner`: Trigger a slow/erroring fixture through the TUI, cancel and retry with both input paths, and assert the screen and journal show the correct outcome with no leaked child. Run fresh fixtures for keyboard and mouse paths and verify equivalent outcomes at 120x40 and 80x24 where applicable.
3. Run `cargo test --test tui_e2e process_runner -- --nocapture` and verify a nonzero selected test count; run the relevant code/provider tests and `cargo test --all-targets`. Record actual results and failure artifacts before completion. The initial framework is delivered by the bootstrap/framework prerequisites.
<!-- SECTION:DESCRIPTION:END -->
