## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Reviewers need to follow discussion at the code location and distinguish unresolved, resolved, and outdated threads. Thread actions must affect the intended server resource.

## Testing steps

1. Code/provider tests: Test thread identity and pagination, permissions, resolve/unresolve/reactions, and outdated anchors.
2. Real-binary TUI E2E scenario `review_threads`: Open a thread from a diff, reply/react/resolve/reopen via keys and clicks, then verify command IDs and consistent diff/timeline states after refresh. Run fresh fixtures for keyboard and mouse paths and verify equivalent outcomes at 120x40 and 80x24 where applicable.
3. Run `cargo test --test tui_e2e review_threads -- --nocapture` and verify a nonzero selected test count; run the relevant code/provider tests and `cargo test --all-targets`. Record actual results and failure artifacts before completion. The initial framework is delivered by the bootstrap/framework prerequisites.
