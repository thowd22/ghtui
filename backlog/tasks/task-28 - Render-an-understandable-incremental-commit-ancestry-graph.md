## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The user needs to see Git relationships without learning git log syntax. A graph should explain actual parentage and refs, even when history is large or incomplete.

## Testing steps

1. Code/provider tests: Use real Git DAGs and graph layout tests to assert parent edges, ref labels, pagination continuity and incomplete boundaries.
2. Real-binary TUI E2E scenario `commit_graph`: Navigate commits and parents using keys/clicks/wheel, expand history after resize, and assert correct explanation/details and unchanged working tree. Run fresh fixtures for keyboard and mouse paths and verify equivalent outcomes at 120x40 and 80x24 where applicable.
3. Run `cargo test --test tui_e2e commit_graph -- --nocapture` and verify a nonzero selected test count; run the relevant code/provider tests and `cargo test --all-targets`. Record actual results and failure artifacts before completion. The initial framework is delivered by the bootstrap/framework prerequisites.
