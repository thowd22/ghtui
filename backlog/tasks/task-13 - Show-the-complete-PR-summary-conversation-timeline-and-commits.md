## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Reviewers need one coherent context for a PR before deciding what to do. Missing comment/timeline pages or a confused base/head can make a review incorrect.

## Testing steps

1. Code/provider tests: Check multi-page event ordering, deleted authors, edited/outdated content, permission fields, and head changes.
2. Real-binary TUI E2E scenario `pr_detail`: Open a PR, visit each detail section and expand a long thread by keys and clicks, then return to the selected inbox row and assert complete content. Run fresh fixtures for keyboard and mouse paths and verify equivalent outcomes at 120x40 and 80x24 where applicable.
3. Run `cargo test --test tui_e2e pr_detail -- --nocapture` and verify a nonzero selected test count; run the relevant code/provider tests and `cargo test --all-targets`. Record actual results and failure artifacts before completion. The initial framework is delivered by the bootstrap/framework prerequisites.
