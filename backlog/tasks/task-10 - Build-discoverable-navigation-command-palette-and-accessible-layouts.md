## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Users with little Git knowledge should discover actions and keep their place without learning modal keybindings. All screens need a consistent mouse and keyboard route.

## Testing steps

1. Code/provider tests: Test navigation history, focus/action availability, Unicode display width, and narrow/wide snapshots.
2. Real-binary TUI E2E scenario `navigation`: Complete the same view/palette/back/help journey with keys and clicks at both sizes and assert selection/focus survives resize. Run fresh fixtures for keyboard and mouse paths and verify equivalent outcomes at 120x40 and 80x24 where applicable.
3. Run `cargo test --test tui_e2e navigation -- --nocapture` and verify a nonzero selected test count; run the relevant code/provider tests and `cargo test --all-targets`. Record actual results and failure artifacts before completion. The initial framework is delivered by the bootstrap/framework prerequisites.
<!-- SECTION:DESCRIPTION:END -->
