## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
GitHub requests, Git reads, scanning, and indexing can take seconds. The terminal must continue responding while those operations run and ignore results from superseded selections.

## Testing steps

1. Code/provider tests: Drive reordered completions, queue saturation, cancellation, and concurrent failures through domain/event tests. Verify the existing prepared-form documents use bounded borrowed visible rows, preserve exact Unicode/source anchors and reject expired/cancelled preparation without renewing budgets.
2. Real-binary TUI E2E scenarios `async_events` and `form_preview_visible`: Delay a fixture request, switch views and cancel by keyboard and mouse, asserting the shell stays responsive and late results never replace the current screen. Exercise long prepared previews through deep scrolling and 120x40/80x24 resize with fresh fixtures for both input paths; independently assert exact draft bodies, command journals, Git/SQL/config effects and terminal restoration. No snapshot-only substitute.
3. Run node scripts/test-task.mjs async_events and node scripts/test-task.mjs form_preview_visible (and checked new scenarios if implementation adds behavior), cargo test --test tui_e2e async_events -- --nocapture, relevant code/provider tests, and cargo test --all-targets via node scripts/test-all.mjs. Run cargo fmt --check and cargo clippy --all-targets -- -D warnings; verify nonzero selected counts and no ignored required tests. Record actual results/source/artifacts before completion. Root alone holds the shared verification lock and verified host limits.

Linux development readiness is provided by completed TASK79. Original native macOS foundation acceptance remains required before release; this task does not waive it or claim a measured application latency budget.
