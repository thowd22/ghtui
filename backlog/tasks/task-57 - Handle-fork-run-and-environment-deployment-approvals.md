## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Workflows can wait on a human decision. The TUI should show what approval is needed, who can give it and which run/environment will proceed.

## Testing steps

1. Code/provider tests: Test pending-deployment IDs, permissions, self-approval restrictions, stale run state and partial multi-environment results.
2. Real-binary TUI E2E scenario `actions_approvals`: Open a waiting run, inspect gates and approve/reject via keys/clicks in separate fixtures; verify target payload, actor display and refreshed status. Run fresh fixtures for keyboard and mouse paths and verify equivalent outcomes at 120x40 and 80x24 where applicable.
3. Run `cargo test --test tui_e2e actions_approvals -- --nocapture` and verify a nonzero selected test count; run relevant code/provider tests and `cargo test --all-targets`. Record actual results and failure artifacts before completion. Use the shared framework established by the bootstrap/framework prerequisites.
