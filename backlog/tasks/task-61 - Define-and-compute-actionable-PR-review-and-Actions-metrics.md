## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Metrics should answer useful questions and link to evidence. Current snapshots cannot be presented as complete historical trends, and missing data must not silently become zero.

## Testing steps

1. Code/provider tests: Compute against fixed timestamp/event fixtures including reopened/draft PRs, rerun attempts, missing events and partial scopes.
2. Real-binary TUI E2E scenario `metrics`: Change metric scope/window with keys/clicks, open a value, and assert exact contributing records, usernames and displayed incomplete-data state. Run fresh fixtures for keyboard and mouse paths and verify equivalent outcomes at 120x40 and 80x24 where applicable.
3. Run `cargo test --test tui_e2e metrics -- --nocapture` and verify a nonzero selected test count; run relevant code/provider tests and `cargo test --all-targets`. Record actual results and failure artifacts before completion. Use the shared framework established by the bootstrap/framework prerequisites.
