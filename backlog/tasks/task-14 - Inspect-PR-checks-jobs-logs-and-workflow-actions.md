## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
A PR may look ready while checks are pending, stale, or failed. Reviewers need clear status tied to the PR head and immediate access to the useful failure log.

## Testing steps

1. Code/provider tests: Test stale-SHA checks, pending/skipped states, pagination/log limits, permission failures, and rerun/cancel commands.
2. Real-binary TUI E2E scenario `pr_checks`: Open a failing check and log, search/scroll it, rerun or cancel through keys and clicks in fresh fixtures, and assert the command target and refreshed status. Run fresh fixtures for keyboard and mouse paths and verify equivalent outcomes at 120x40 and 80x24 where applicable.
3. Run `cargo test --test tui_e2e pr_checks -- --nocapture` and verify a nonzero selected test count; run the relevant code/provider tests and `cargo test --all-targets`. Record actual results and failure artifacts before completion. The initial framework is delivered by the bootstrap/framework prerequisites.
<!-- SECTION:DESCRIPTION:END -->
