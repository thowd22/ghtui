## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Cached data makes the interface fast and useful offline, but stale data and account switching must not lead to misleading results or lost review drafts.

1. Code/provider tests: Test migrations, interrupted writes, stale refresh, account namespace isolation, and draft preservation.
2. Real-binary TUI E2E scenario `cache_storage`: Load cached data with a delayed/offline provider, refresh or clear cache by keys and clicks, switch identity, restart, and assert visible scope and persisted records.
