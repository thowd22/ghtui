## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Every feature must be testable while it is built. Extend the bootstrap PTY test into reusable offline helpers that exercise real event handling, subprocess boundaries, storage effects, mouse behavior, and keyboard behavior.

## Testing steps

1. Code/provider tests: Test fixture scripts, matching, Git builders, cleanup, and test-key coverage checks including deliberate violations.
2. Real-binary TUI E2E scenario `test_framework`: Use the real shell to navigate by keys and clicks, inject a provider failure and resize, then verify screen/state assertions fail when the expected behavior is deliberately wrong. Run fresh fixtures for keyboard and mouse paths and verify equivalent outcomes at 120x40 and 80x24 where applicable.
3. Run `cargo test --test tui_e2e test_framework -- --nocapture` and verify a nonzero selected test count; run the relevant code/provider tests and `cargo test --all-targets`. Record actual results and failure artifacts before completion. The initial framework is delivered by the bootstrap/framework prerequisites.
