## Avatar transport, limits and cache

GitHub API calls and authentication remain exclusively with `gh`. `CurlAvatarFetcher` is an optional public-image transport discovered from the installed PATH; `curl` is not a mandatory dependency. It runs via the bounded shared command adapter with separate argv, no inherited environment/auth/proxy/cookie settings, curl configuration disabled by initial `-q`, HTTPS only, no redirect following, an explicit image Accept header and bounded connection/request time. Trusted public hosts default to avatars.githubusercontent.com and github.com; untrusted/private/authenticated URLs fail to initials. Additional enterprise asset hosts require an explicit trusted-host policy. Redirect-only, authenticated, unsupported-format or unavailable assets use the honest fallback.

Only PNG/JPEG assets decode. Encoded bytes are bounded to1MiB; strict image dimensions are at most512px per side, with a4MiB decoder allocation limit. Prepared cached pixels are resized only when larger than64px, preserving small image dimensions and real pixels. Malformed/oversized assets fail without delaying text. Unsupported GIF/WebP or terminal image protocols are not claimed.

`AvatarCache::request` performs no disk/network/decoding work on the rendering thread. Four cancellable background workers deduplicate requests, keep at most128 in-memory records and persist exact account/host/identity/source provenance alongside prepared pixels. Cached records have bounded sizes and expire on disk after24hours. Corrupt or mismatched records refetch. Valid generated disk records are evicted to128; unrelated or malformed files are preserved. Storage failures leave a valid fetched image usable. Failed requests require an explicit retry; no network storm or offline mutation queue is created. Worker panics become a visible fallback failure rather than permanent Loading. AvatarCache::shutdown atomically prevents new requests, cancels tokens and joins tracked workers before quit/account/scope replacement; the production fetcher uses bounded cancellation deadlines.

`ActorWidget` reserves a layout-assigned4x2 avatar rectangle and keeps username text visible. `AvatarWidget` renders the actual bounded image using Unicode half blocks with foreground/background pixel colors, which require no Kitty/iTerm/Sixel negotiation or extra image executable. Initials remain available during load/failure, in narrow layouts and in low-color/no-color mode. This is a small native raster preview, not high-resolution terminal-image rendering.

## Semantic meaning

`src/theme.rs` centralizes normal/muted/add/remove/modify/conflict/HEAD/ref/ancestor/divergence and CI success/failure/running/pending/cancelled tokens. Dark/light true-color, low-color and no-color styles retain symbols and labels. Selection preserves semantic foreground/background and adds a visible overlay. Native graph palette slots continue the parent paths already tracked by the graph model; the legend explicitly explains that lanes are not permanent branch identities.

True-color status text uses measured contrast of at least4.5:1 against its explicit dark/light background. Low-color terminal palettes are user-controlled; redundant labels and symbols carry the meaning. No-color avoids color styling and keeps the same status words and navigation controls. ColorMode::for_terminal uses explicit captured TERM/COLORTERM/NO_COLOR capabilities outside drawing; truecolor/24bit/direct choose RGB, other non-dumb terminals use the semantic low-color palette, and dumb/NO_COLOR choose monochrome. Native images use initials unless true-color is available.
