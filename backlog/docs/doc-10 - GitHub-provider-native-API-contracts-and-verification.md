# GitHub provider implementation and integration contract

This is an implementation checkpoint, not a claim of finished PR/Actions parity. All GitHub requests and authentication use installed `gh`; local Git remains available without authentication. No live GitHub mutation, remote creation, or disposable-repository integration test has been performed. Native app forms and task-specific real-binary keyboard/mouse journeys must verify the prepared operations before any relevant task is Done.

## Modules and stable identity

- `src/providers/runner.rs`: explicit argv/stdin, process-group cleanup, combined output budgets, deadlines including queued write time, cancellation, coalesced reads with independent subscriber cancellation, per-resource write serialization, secret/terminal-text redaction, and reconciliation barriers.
- `src/providers/gh.rs`: host/account identity, repositories, personal authored/assigned/review-requested queues, complete paginated PR reads, canonical SHA-bound diffs/checks, baseline lifecycle/review/merge, remote Git trees/blobs, baseline runs/logs.
- `src/providers/gh/pr.rs`: typed metadata, reviewers/teams, comment/reaction/subscription, canonical multiline inline/pending comments, review lifecycle, thread/viewed-file state, lock/update/revert/create PRs and project item addition.
- `src/providers/gh/actions.rs` and submodules: exact run/attempt/job controls, annotations, definitions/dispatch, artifacts, cache/approvals, secrets/variables, policy/environment/runner settings.
- `src/providers/gh/search.rs`: explicitly labelled remote discovery and exact code-blob-to-commit verification.

Serializable records retain host, resource IDs, repository full names, actor roles, canonical paths, PR head/base SHAs, run SHA/attempt/job IDs and coverage. Repository owners are not presented as file authors. Actor usernames/avatar URLs remain data, not an authentication mechanism.

`pr_context(&PrSummary, cancel)` separately hydrates repository permissions, issue metadata, requested reviewers/teams, head/base repositories (a deleted fork is None), maintainer edit ability, immutable comparison identities and source URLs. It validates node ID and both SHAs before/after loading. This avoids forcing expensive metadata requests into inbox startup.

## Mutation handling

Current account and selected resource state are freshly read before mutation. JSON/form bodies use stdin rather than shell interpolation. PR metadata edits omit unchanged fields; edits reject conflicting observed state. Inline comments use canonical patch paths/old or new coordinates and commit IDs, never transformed display coordinates. Pending review additions omit a publication event; submitting an outdated pending review is blocked while discarding is permitted.

An exit error, timeout, cancellation, malformed successful write response, GraphQL errors, failed post-write observation or incompatible readback must not become an automatic duplicate mutation. The common runner retains a per-resource reconciliation barrier when outcome is ambiguous. The UI must refresh the exact affected resource and explicitly acknowledge the observed outcome. GitHub has asynchronous operations: `RunMutationOutcome` and `DispatchOutcome` distinguish acceptance from an observed completed transition. Branch update returns an accepted asynchronous request; unchanged immediate head is not proof that the branch update finished.

Client state checks cannot make all REST metadata writes atomic. Server-side expected-head conditions are used where supported; permission/rules enforcement remains with GitHub. UI confirmations must still show exact scope, effect, selected ID and current account.

## Prepared native APIs

| Area | Typed provider API |
| --- | --- |
| Run catalog | `run_catalog(repo, RunFilter, cancel)` gives runs and explicit filtered-search coverage |
| Attempts/jobs | `run_attempt(repo, run_id, attempt, cancel)` verifies each typed job belongs to that run/attempt/SHA |
| Logs/annotations | `run_logs_at(repo, run, Option<Job>, cancel)`, `job_annotations(repo, Job, cancel)` |
| Run controls | `mutate_run(identity, repo, run, RunMutation, cancel)`: all/failed/specific-job debug rerun, cancel/force cancel, delete run/logs and fork approval |
| Workflow YAML | `workflow_definition(repo, Workflow, revision, cancel)` resolves the ref to a commit and loads that immutable YAML |
| Dispatch/state | `dispatch_workflow`, `set_workflow_enabled`; typed boolean/number/string/choice/environment/default validation |
| Artifacts | `artifacts`, `artifact`, `download_artifact`, `delete_artifact`; `ArtifactArchive` preview/export/extract |
| Approval gates | `pending_deployments`, `review_deployments(DeploymentReview)`; permission/self-approval restrictions and partial pending state remain explicit |
| Cache | `action_caches`, `cache_usage`, `delete_cache`; exact selected ID/key/ref and byte units |
| Secret metadata | `secret_metadata`, `set_secret(SecretUpdate, transient_value)`, `delete_secret`; no existing value retrieval model |
| Variables | Scoped list/read/create/update/delete, observed-value comparison, organization policy metadata |
| Policy/runner settings | Typed `PolicyEdit`, `EnvironmentEdit`, runner labels/removal, runner groups and exact membership replacement |
| Remote search | `remote_search(identity, Query, RemoteSearchKind, selected_repos, cancel)`, `resolve_remote_code(item, cancel)`, `resolve_remote_content(item, max_bytes, cancel)` |

Workflow YAML uses pinned official `yaml-rust2` 0.11.0, UTF-8 only. Event/depth/expanded-alias accounting runs before tree construction: 512 KiB source, 64 nesting levels and bounded expansion. Dispatch inputs are validated against the selected YAML, with up to 25 fields and a 65,535-byte budget. The selected ref must still resolve to the inspected commit. Current REST documentation returns a workflow run ID from dispatch; older hosts may return empty acceptance, which is labelled uncorrelated rather than guessed. [Workflow REST reference](https://docs.github.com/en/rest/actions/workflows), [workflow syntax](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax).

Artifact bytes stay behind `gh api` transport. ZIP inspection uses pinned official `zip` 2.4.2; defaults cap compressed download at 16 MiB, total expansion at 64 MiB, each entry at 16 MiB, preview at 256 KiB, 4,096 entries and a 200x ratio. Absolute/traversing/ambiguous paths, backslashes, drive-like prefixes, duplicate/case-colliding names, links, special files, encrypted entries and file-as-parent conflicts are rejected. Supported SHA-256 digest metadata is verified against downloaded bytes. Extraction completes actual size/CRC checks in a private staging directory before publishing a newly created destination. No implicit overwrite; ZIP export uses atomic no-clobber persistence. Executable permissions are not restored and downloaded content is never executed. Artifact attempt identity remains optional because the documented API does not provide an authoritative attempt field. [Artifacts REST reference](https://docs.github.com/en/rest/actions/artifacts).

Secret input is transient stdin to native `gh secret set`; the runner redacts even non-token-looking values from stdout/stderr. Production models contain only secret names/timestamps/visibility. Strict fixtures verify synthetic input bytes but automatically redact secret-set stdin from their command journals. Existing secret values cannot be read; organization visibility/membership is explicit. [gh secret set](https://cli.github.com/manual/gh_secret_set), [Secrets REST reference](https://docs.github.com/en/rest/actions/secrets), [Variables REST reference](https://docs.github.com/en/rest/actions/variables).

Recent gh raw-output guarding rejects escape-bearing raw bodies even when consumed as a pipe. Bounded binary/YAML/blob reads request `--allow-escape-sequences`, then ghtui safely inspects/sanitizes displayed data. Only an older CLI rejecting that unknown flag before HTTP permits a read-only retry without the flag; writes never receive this fallback. [Official gh v2.101 API source](https://github.com/cli/cli/blob/v2.101.0/pkg/cmd/api/api.go).

Remote search only accepts explicit GitHub mode. Unsupported regex/revision/comment/set constraints are errors, not discarded filters. PR/issue modes enforce resource type; selected repositories remain scope boundaries. Paging, changing totals, server incomplete flags and the 1,000-match API cap are visible. Legacy code search uses indexed default-branch files under 384 KiB; a returned SHA is a blob identity, not a commit. File navigation separately resolves a commit and verifies that exact blob at the canonical path, otherwise reports stale indexed content. Server fragment offsets are not invented full-file lines. [Search REST reference](https://docs.github.com/en/rest/search/search).

## Authentication and private caches

`gh auth status --active --hostname HOST --json hosts` is not a reliable local-only startup identity shortcut: current official source still performs HTTP probes; JSON success does not itself prove account validity. Private cached records remain hidden until `gh api user` supplies a positive durable numeric account ID. `HostIdentity.account_id` is explicitly None when missing/zero/non-numeric; host plus mutable username is not a strong cache principal. Remote guards compare host, login and ID, rejecting same-login reassignment and unverified-to-verified transitions. No extra authentication implementation or token extraction is added. [Durable user ID REST contract](https://docs.github.com/en/rest/users/users#get-a-user-using-their-id). No tokens are extracted/stored by ghtui. [gh auth status](https://cli.github.com/manual/gh_auth_status), [official status implementation](https://github.com/cli/cli/blob/v2.101.0/pkg/cmd/auth/status/status.go).

## Exact authenticated remote file content

`resolve_remote_content(item, max_bytes, cancel)` returns `ResolvedRemoteContent { file, bytes }` and reuses the resolver's three gh reads: repository/default branch, immutable commit, exact Contents response. It rejects changed repository names instead of silently following a redirect; validates canonical path/type/blob and declared size; bounds encoded and decoded allocation; permits only documented base64 line breaks; and independently hashes the actual canonical Git blob header plus bytes. Public `verify_blob_digest` supports legacy SHA1 addressing through pinned RustCrypto sha1 0.10.6 and SHA256 through the existing implementation. SHA1 is not introduced for authentication. The caller must guard account identity before/after loading and retain non-UTF8/binary state honestly. No download URL, authenticated image client or arbitrary HTTP client substitutes for gh. The hard content maximum is 2 MiB; hosts that return encoding none for larger Contents objects are explicitly unsupported here rather than silently fetching different content. [Contents response contract](https://docs.github.com/en/rest/repos/contents#get-repository-content), [canonical Git object addressing](https://git-scm.com/book/en/v2/Git-Internals-Git-Objects), [Git SHA256 transition](https://git-scm.com/docs/hash-function-transition).
