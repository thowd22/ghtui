# Scoped search backend API and verification

## Canonical identity and semantics

src/search/model.rs provides DocumentKey, Document, Metadata, Destination, SearchHit, Coverage and SavedSearch. Document keys include host/account/repository/revision/result-kind/raw-path/resource, and stable hashes serialize those exact fields rather than formatted labels. RawPath serde retains arbitrary Unix filename bytes. Local saved-file destinations require immutable40/64-digit commit identities and exact raw paths; working-file destinations are explicitly mutable. PR/issue/comment/thread/run destinations retain their exact host/repository/resource context. Metadata filter groups are AND across fields and OR within repeated values of a field. Unknown/unsupported remote semantics produce validation errors; no Regex or revision query is weakened into legacy GitHub search.

A GitHub legacy code-search sha identifies a blob, not a commit. Provider-owned gh/search.rs returns unresolved remote candidates distinctly and resolves/validates exact commit+contents before an exact RemoteFile destination can be constructed. Repository-owner actors are not code authors. GitHub API authentication/transport remains exclusively gh.

## Read-only corpus and embedded matching

src/search/corpus.rs collects explicitly selected existing Git repositories. RepositorySelection retains repository name, directory, LocalSource::Worktree or Revision and repository sets. Worktree collection uses embedded ripgrep ignore handling (.gitignore/.rgignore/local excludes/global ignores), explicit hidden/ignored controls, non-following symlink handling and regular-file checks. It never reads .git internals as searchable code. Git-object collection resolves a saved commit once, reads the tracked tree, preflights blob sizes using batched GitRepository::object_sizes and reads bounded batches without checkout. Saved-tree scope intentionally does not inherit current working ignore rules.

Configurable limits bound file bytes,total bytes and document counts. Missing repositories/objects, cancellations and budgets become coverage reasons. Binary/invalid-UTF8 data, symlink/submodule/special objects and LFS pointers are excluded with visible counts; no LFS payload download occurs. Local reads now set GIT_NO_LAZY_FETCH plus an empty GIT_ALLOW_PROTOCOL fallback for older Git, preventing hidden promisor transport. Explicit authorized fetch/write and targeted force-lease ls-remote reads remain separate.

src/search/scan.rs uses embedded grep-regex/grep-searcher/grep-matcher. Exact literals and bounded Regex have different semantics, Unicode character columns and canonical line numbers. Multiline matches retain their first exact location and bounded prepared snippets. Byte-offset highlights preserve UTF-8 boundaries. Invalid regex, match/byte limits and cancellation are explicit. Ranked and GitHub modes use their own providers; local Exact/Regex never pretend to rank semantically.

## Application integration API

search::workspace::SearchWorkspace exposes scope,selections,available_selections,input,mode,corpus_limits,scan_limits,page,preview,saved,warnings. Construct with new(scope,selections) or worker-only from_config(scope,config,cwd,cancellation). No clone/fetch occurs during discovery. Unmapped current checkouts use the honest local/current label, not a guessed GitHub repository identity.

search(input,cancellation) performs collection and matching on a background worker. set_mode/set_source discard stale displayed results. Explicit rev filters require saved-version scope and are resolved per repository into exact commits; mutable working files never silently become snapshots. preview(index) and destination(index) use prepared source data and retain exact result context, with no I/O during drawing. SearchAction covers Query/Mode/Worktree/Revision/Submit/Preview/Open/Save/Saved/Corpus so both input paths can dispatch the same actions.

Saved searches live under search:name in account-scoped SQLite saved_views. They preserve mode/input/filters/repository selection/per-repository source/sort/pin. Reopening a missing repository does not broaden scope. Available mappings are retained separately so one saved query does not erase another's access context.

src/search/fuzzy.rs uses actual Nucleo only for navigation pickers. It has smart Unicode normalization/case, explicit candidate/query/label/result limits, deterministic score/label/ID ties, cancellation and Unicode character indices. It does not substitute fuzzy matching for code-content relevance.

## Current prepared derivative and memory model

SearchHit.document now uses Arc<Document>. Exact/Regex allocates one shared source copy only after a file matches; every occurrence shares that same source body and keeps a bounded independent snippet. A meaningful 2MiB/1000-occurrence contract asserts identical Arc pointers and only6000 snippet bytes. This new contract is pending coordinated rerun, not historical passing evidence.

Replacement refs/grafts are explicitly reported by Corpus coverage and Metadata.history_overrides. Saved collection uses original Git objects and preserves exact raw paths/SHA; working scope keeps installed-Git semantics. TASK-72 contains generated original-versus-effective Git/search contracts and actual both-input PTY journeys, currently awaiting coordinated verification.

Local file DocumentKey.resource includes a SHA256 of actual repository directory bytes. Linked worktrees with identical GitHub repo/path/HEAD but different working contents and navigation destinations cannot overwrite one another in the shared derivative. A generated linked-worktree contract asserts the distinct identities and exact destinations.

src/search/index.rs exposes RankedIndex::open(index_root,scope,cache,RankedLimits,cancel), publish(cache,source,generation,corpus,cancel), next_generation(cache,scope,source), search_source(source,query,cancel), IndexStatus and PublishSummary. One account-scoped Tantivy derivative serves source memberships; no selected search can broaden to another corpus. Canonical SQLite source frames publish atomically; complete updates remove missing identities and partial updates retain previous members. Fingerprints incrementally replace changed content; rewritten saved refs change canonical SHA keys. Budgets preflight the account union before source publication. A nonblocking OS lock avoids blocking TUI input behind another writer. Cancellation before publication preserves the source generation; cancellation after canonical commit rolls back derivative writes, and reopening repairs the stale derivative before exposing results.

Only explicitly marked account-owned derivative directories can be quarantined on corruption/schema incompatibility. Quarantined bytes are retained; source records/drafts are not deleted. Index checksums are validated during worker-only open; this has bounded but real disk cost, not zero-I/O startup. Ranked snippets/fields retain canonical destinations; full sources are shared Arc values. Tantivy BM25 is lexical relevance, not semantic question answering or Google-scale completeness.

src/search/tokenizer.rs uses lazy bounded streams with separate full-identifier and snake/camel/acronym/numeric/path-part positional fields. Tokens beyond255 Unicode scalars are intentionally not indexed. Exact title/path/body and readable-part fields have explicit boosts; terms are individually quoted to prevent raw Tantivy operators escaping scoped filters, and score ties use exact stable document keys. Matched-field explanations and bounded snippets preserve Unicode offsets/coordinates. Four embedded search_index contracts plus two search_relevance contracts are prepared/exported but not yet verified; actual ranked keyboard/mouse integration and full gates remain mandatory.

## Resource-bound discussion read/write visibility (current prepared native integration)

Cache schema4 adds canonical resource bindings separate from stored document bytes. A binding scopes the positive numeric principal, repository database ID/name, exact PR/issue parent node and closed body/comment/review/inline category. Reserve before gh reads. Only an atomic current reserved publication assigns visible_generation; cached source admission requires that generation to equal the canonical checkpoint, not the reservation active flag. Clearing/revocation and exact-category text invalidation preserve intentional drafts/receipts while fencing derived in-flight index reads. A new reservation cannot revive old hidden bytes; partial hydration must explicitly suppress previously unadmitted members.

PR native and legacy publication controllers invalidate genuine changed-text categories immediately after durable confirmation and before optional gh refresh. Called uncertain publication/receipt-failure paths can conservatively fence possible text, but a pending-before-send marker alone does not establish invocation or a remote effect. Confirmed receipt ordinals deduplicate replay: restoring the same original publication never resends and never hides newer explicitly hydrated text. Reactions, subscription and base changes do not pretend to change discussion text.

Worker-facing pr_projection guard_discussion_reads(database, positive_scope, targets) repairs missing confirmed visibility fences before cached collection/hydration, using only latest closed receipt metadata per category, at most8KiB per receipt and256 targets per worker batch. Issue sources never become PR sources from matching numbers. DiscussionReadGuard exposes blocked_sources(), status() and recovered_sources(); pending text is honestly unavailable, not confirmed or acknowledged. validate_discussion_read_guard(database, guard) rechecks opaque database/per-PR journal generations before prepared metadata admission, including races whose SQLite visibility fence failed. Root source workers additionally guard fresh account identity and use bounded chunks for larger explicit sets. No raw cached body, review draft or transport diagnostic is required for these guards.
