## Evidence axes and limits

1. Public documentation confirms an operation exists, not that the installed CLI, selected host, repository plan/rules or current caller permits it. Current documentation may default to the 2026-03-10 REST API; the application retains its existing version header. No compatibility is inferred by silently changing that header.
2. The 33-category inventory maps all 16 PR and 12 Actions rows. Its permissions/guards are requirements; legacy implemented flags are not native/live authority. Unknown minimum operation/GHES versions remain unknown. Every actual operation must validate fresh principal, original target, permissions/state and schema; missing data is not support.
3. Fixture examples below were found as actual successful test lines in the completed unfiltered current-source run. An example proves its exercised subset only, NOT every suboperation, complete native UX or live-host behavior. Suggestion application and isolated PR conflict editing have no product-flow example and stay explicit gaps.
4. All native workflow tasks retain their own keyboard/mouse and effect/recovery acceptance. No browser handoff, generic arbitrary command or this ledger closes them. Live mutation evidence remains opt-in and requires an explicitly configured disposable repository.

The current [CLI PR manual](https://cli.github.com/manual/gh_pr) documents a revert command; the tested adapter in this checkout instead uses the documented GraphQL mutation. Command existence is not evidence of its minimum supported version. The old generic `/graphql/reference/mutations` URL redirected to the reference index during review; use the current [pulls](https://docs.github.com/en/graphql/reference/pulls), [projects](https://docs.github.com/en/graphql/reference/projects) and [activity](https://docs.github.com/en/graphql/reference/activity) categories. The [public-schema download](https://docs.github.com/en/graphql/overview/public-schema) was additionally inspected read-only for those mutation names; it is not target-host introspection.

Permission classes must not collapse all settings into one grant: pending-environment decisions document Deployments-write; organization secret membership uses scoped Secrets plus repository metadata requirements; variable, environment, Actions-policy and runner/group operations have their own eligible scopes. Environment protection also depends on plan/repository visibility. The exact linked endpoint documentation and live response, not a broad inspector label, govern actual eligibility. ghtui never extracts tokens to attempt permission inference.
